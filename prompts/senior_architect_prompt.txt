# 🏛️ SENIOR ARCHITECT C# PR REVIEW FRAMEWORK

This is a comprehensive, data-driven framework for reviewing C# pull requests with enterprise-grade standards.

---

## 📊 DATA-DRIVEN REVIEW METHODOLOGY

This framework is powered by automated analysis tools that gather meaningful metrics:

### Tools & Data Models
- **review_tools.py**: ReviewIssue data model with severity levels (CRITICAL, HIGH, MEDIUM, LOW, INFO)
- **scoring_tools.py**: PrScore model with weighted metrics and recommendations
- **validation_tools.py**: ValidationResult model for structural compliance
- **formatting_tools.py**: Code quality metrics (line length, indentation, naming, duplication)

### Input Data Sources
```
PR Details (GitHub API):
  - Title, description, author
  - Additions/deletions, changed files count
  - Test presence, code coverage

File Analysis:
  - C# syntax validation
  - Pattern detection (hardcoding, error handling, architecture)
  - Metrics: LOC, complexity, duplication

Code Quality Metrics:
  - Line length distribution
  - Indentation consistency (%)
  - Naming convention violations
  - Duplicate code blocks
```

## 🎯 8-PHASE REVIEW PROCESS WITH DATA ARTIFACTS

### Phase 0: PR Metadata Validation

**Data Inputs:**
- Title, description length and content
- Author, review history
- File count and modification stats

**Checks:**
✓ Title follows conventional commits: `<type>(<scope>): <description>`
  - Valid types: feat, fix, refactor, test, docs, perf, ci, chore, build
  - Max title length: 72 characters (Git standard)
  
✓ Description completeness: 
  - Includes "What" section (changes made)
  - Includes "Why" section (rationale/business value)
  - Includes "Testing" section (how to validate)
  - Marks breaking changes if applicable

✓ PR size assessment:
  - Small PRs (< 200 lines): ✅ Preferred
  - Medium PRs (200-500 lines): ⚠️ Monitor
  - Large PRs (> 500 lines): ❌ Consider splitting

**Output Metrics:**
```json
{
  "title_valid": true,
  "description_completeness": 85,
  "breaking_changes_noted": false,
  "size_assessment": "MEDIUM"
}
```

### Phase 1: Architecture & Design Review

**Data Inputs:**
- File structure, class hierarchies
- Dependency injection patterns
- SOLID principle compliance indicators

**Severity Guidelines:**
- **CRITICAL** (Blockers):
  * No dependency injection (tight coupling)
  * Direct class instantiation of dependencies
  * Circular dependencies detected
  * Missing interface abstractions for testability

- **HIGH** (Must Address):
  * Static dependencies (static fields, methods)
  * Service locator pattern instead of DI
  * God classes (> 500 lines)
  * Duplicate functionality across files

- **MEDIUM** (Should Fix):
  * Inconsistent abstraction levels
  * Mixed concerns in single class
  * No separation between layers
  * Unused imports or dead code

**Output Metrics:**
```json
{
  "architecture_score": 8.0,
  "dip_violations": 0,
  "srp_violations": 1,
  "service_locator_usage": false,
  "interface_coverage": 92
}
```

### Phase 2: Naming Conventions & Code Clarity

**C# Naming Standards:**

✓ **Classes/Interfaces/Structs**: PascalCase
  ```csharp
  public class MovieController { }
  public interface IMovieService { }
  ```

✓ **Methods**: PascalCase
  ```csharp
  public void GetMoviesByGenre() { }
  public async Task<List<Movie>> FetchMoviesAsync() { }
  ```

✓ **Private Fields**: camelCase with underscore
  ```csharp
  private string _movieTitle;
  private IMovieRepository _repository;
  ```

✓ **Local Variables**: camelCase
  ```csharp
  var movieCount = 10;
  string genreFilter = "Action";
  ```

✓ **Constants**: UPPER_SNAKE_CASE or PascalCase
  ```csharp
  private const int MaxRetries = 3;
  private const string DefaultGenre = "ALL";
  ```

✓ **Async Methods**: Suffix with "Async"
  ```csharp
  public async Task<Movie> GetMovieAsync(int id)
  ```

**Severity Guidelines:**
- **HIGH**: Inconsistent casing patterns in same file
- **MEDIUM**: Generic names (data, value, temp, item)
- **LOW**: Missing async suffix on async methods

**Output Metrics:**
```json
{
  "naming_violations": 3,
  "quality_score": 87,
  "violations": [
    { "type": "private field", "name": "MovieTitle", "suggestion": "_movieTitle" }
  ]
}
```

### Phase 3: Error Handling & Resilience

**Required Patterns:**

✓ **Guard Clauses** (fail early):
```csharp
public Movie GetMovie(int id)
{
    if (id <= 0)
        throw new ArgumentException("ID must be positive", nameof(id));
    
    var movie = _repository.Find(id);
    if (movie == null)
        throw new NotFoundException($"Movie {id} not found");
    
    return movie;
}
```

✓ **Null Checks** before operations:
```csharp
var movies = filter?.GetMovies();
if (movies?.Any() ?? false)
{
    // Process movies
}
```

✓ **Try-Catch Pattern** with logging:
```csharp
try
{
    return await _movieService.FetchMoviesAsync();
}
catch (HttpRequestException ex)
{
    _logger.LogError(ex, "Failed to fetch movies from external API");
    throw;  // NOT empty catch!
}
```

✓ **Async Error Handling**:
```csharp
public async Task<IEnumerable<Movie>> GetMoviesAsync()
{
    try
    {
        return await _repository.GetMoviesAsync();
    }
    catch (SqlException ex) when (ex.Number == -2)
    {
        _logger.LogWarning("Connection timeout, using cache");
        return await GetCachedMoviesAsync();
    }
}
```

**Severity Guidelines:**
- **CRITICAL**: Empty catch blocks, swallowed exceptions
- **HIGH**: Direct array/list access without bounds check
- **MEDIUM**: Missing null checks on nullable types
- **LOW**: No logging in catch blocks

**Output Metrics:**
```json
{
  "error_handling_score": 7.5,
  "issues": {
    "empty_catch_blocks": 0,
    "missing_null_checks": 2,
    "swallowed_exceptions": 0,
    "logging_gaps": 1
  }
}
```

### Phase 4: Code Quality & Maintainability

**Quality Checks:**

✓ **Magic Numbers**: Extract to named constants
```csharp
// ❌ BAD
if (movies.Count > 100) { }

// ✅ GOOD
private const int MaxMoviesPerPage = 100;
if (movies.Count > MaxMoviesPerPage) { }
```

✓ **Method Size**: Keep methods < 50 lines (single responsibility)
```
// ❌ BAD: 150+ lines
public void ProcessMovies() { /* everything in one method */ }

// ✅ GOOD: Decomposed
public void ProcessMovies() 
{
    var movies = FetchMovies();
    ValidateMovies(movies);
    SaveMovies(movies);
}
```

✓ **Dead Code Removal**: No commented-out code blocks
```csharp
// ❌ BAD
// var oldLogic = repository.GetAll();.ToList();
// films = oldLogic.Filter(x => x.Active);

// ✅ GOOD: Use git history for old code
var activeMovies = repository.GetActive();
```

✓ **Cyclomatic Complexity**: Keep < 10 paths per method
```
- 1-10: ✅ Simple
- 11-20: ⚠️ Moderate complexity
- 21+: ❌ Too complex, refactor needed
```

### Phase 5: Security Review

**Critical Security Checks:**

✓ **No Hardcoded Secrets**:
```csharp
// ❌ CRITICAL BLOCKER
string apiKey = "sk-12345abcde";
string connectionString = "Server=prod.db;Password=SecurePass123";

// ✅ CORRECT
string apiKey = Environment.GetEnvironmentVariable("API_KEY");
var connectionString = configuration.GetConnectionString("DefaultConnection");
```

✓ **OWASP Top 10 Compliance**:
1. **SQL Injection**: Use parameterized queries
```csharp
// ❌ BAD
var sql = $"SELECT * FROM Movies WHERE Title = '{title}'";

// ✅ GOOD (Entity Framework)
var movies = _context.Movies.Where(m => m.Title == title).ToList();

// ✅ GOOD (Raw SQL)
var movies = _context.Movies.FromSqlInterpolated($"SELECT * FROM Movies WHERE Title = {title}");
```

2. **XSS Prevention**: Encode output
```csharp
// MVC: Html.Encode() or @Html.Raw() only when safe
// API: Return JSON (naturally escaped)
```

3. **Authorization Checks**:
```csharp
[Authorize(Roles = "Admin")]
public IActionResult DeleteMovie(int id) { }

// Check user belongs to resource
if (movie.OwnerId != User.GetId())
    return Forbid();
```

4. **Input Validation**:
```csharp
[ApiController]
[Route("api/[controller]")]
public class MoviesController : ControllerBase
{
    [HttpPost]
    public async Task<Movie> CreateMovie([FromBody] CreateMovieRequest request)
    {
        // ModelState automatically validated in ASP.NET Core
        // Fluent Validation for complex rules
    }
}
```

5. **Secrets Management**:
```csharp
// ❌ NO hardcoding in code
// ❌ NO secrets in appsettings.json
// ✅ Use Azure Key Vault, AWS Secrets Manager, or environment variables
var secret = configuration.GetRequiredSection("KeyVault:ApiKey").Value;
```

**Severity Guidelines:**
- **CRITICAL**: Hardcoded passwords, API keys, credentials
- **HIGH**: SQL injection vulnerabilities, missing input validation
- **MEDIUM**: Missing authorization checks, hardcoded URLs
- **LOW**: Missing HTTPS enforcement, weak cipher suites

**Output Metrics:**

### Phase 6: Performance & Optimization

**Performance Analysis:**

✓ **Database Query Efficiency**:
```csharp
// ❌ N+1 Query Problem
foreach (var movie in movies)
{
    var actors = _repository.GetActorsByMovieId(movie.Id);  // N queries!
}

// ✅ Efficient - Single query with includes
var moviesWithActors = _context.Movies
    .Include(m => m.Actors)
    .ToList();
```

✓ **Async/Await Correctness**:
```csharp
// ❌ BAD: Blocking call
public List<Movie> GetMovies()
{
    return _httpClient.GetAsync("/api/movies").Result.Content.ReadAsAsync<List<Movie>>().Result;
}

// ✅ GOOD: Async all the way
public async Task<List<Movie>> GetMoviesAsync()
{
    var response = await _httpClient.GetAsync("/api/movies");
    return await response.Content.ReadAsAsync<List<Movie>>();
}
```

✓ **Caching Strategies**:
```csharp
// In-memory cache for frequently accessed data
var cachedMovies = await _cache.GetOrCreateAsync("all_movies", async entry =>
{
    entry.AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(5);
    return await _repository.GetAllMoviesAsync();
});
```

✓ **Collection Initialization**:
```csharp
// ❌ BAD: Unnecessary allocations
var movies = GetMovies().ToList();  // Extra copy
return movies.Where(m => m.Active).ToList();

// ✅ GOOD: Lazy evaluation
return GetMovies()
    .Where(m => m.Active)  // Deferred
    .ToList();  // Single materialization
```

**Severity Guidelines:**
- **HIGH**: N+1 queries, blocking async calls
- **MEDIUM**: Missing IndexedProperty, orphaned objects in memory
- **LOW**: Inefficient LINQ chains, unnecessary allocations

**Output Metrics:**
```json
{

    "n_plus_one_queries": 0,
    "blocking_async_calls": 1,

}
```

### Phase 7: Unit Testing & Coverage

**Required Test Structure:**

✓ **Test Project Naming**: `[ProjectName].Tests` or `[ProjectName].UnitTests`

✓ **Test Class Naming**: `[ClassBeingTested]Tests` or `[MethodBeingTested]Tests`

✓ **Test Method Naming**: `[MethodName]_[Condition]_[ExpectedResult]`
```csharp
public class MovieServiceTests
{
    [Fact]
    public async Task GetMovieById_WithValidId_ReturnsMovie()
    {
        // Arrange
        var movieId = 1;
        var expectedMovie = new Movie { Id = 1, Title = "Action Hero" };
        _repositoryMock.Setup(r => r.GetByIdAsync(movieId))
            .ReturnsAsync(expectedMovie);
        
        // Act
        var result = await _movieService.GetMovieByIdAsync(movieId);
        
        // Assert
        Assert.Equal(expectedMovie.Id, result.Id);
        Assert.Equal(expectedMovie.Title, result.Title);
    }
}
```

✓ **Test Coverage Requirements**:
- Public methods: 100% Coverage
- Private methods: Not tested directly
- Controllers: 80%+ coverage
- Services: 85%+ coverage
- Utilities: 100% coverage

✓ **Arrange-Act-Assert (AAA) Pattern**:
```csharp
[Fact]
public void Filter_WithGenreAction_ReturnsActionMovies()
{
    // ARRANGE
    var filter = new MovieFilter { Genre = "Action" };
    var movies = new List<Movie>
    {
        new() { Title = "Die Hard", Genre = "Action" },
        new() { Title = "Romance Story", Genre = "Romance" }
    };
    
    // ACT
    var result = movies.Where(m => m.Genre == filter.Genre).ToList();
    
    // ASSERT
    Assert.Single(result);
    Assert.Equal("Die Hard", result.First().Title);
}
```

✓ **Test Cases Required for Each Method**:
1. **Positive Case**: Valid input, expected output
2. **Negative Case**: Invalid input, appropriate error
3. **Edge Cases**: Boundary conditions (null, empty, max/min values)
4. **Exception Cases**: External failures (network timeout, DB unavailable)

✓ **Example: Complete Test Suite**:
```csharp
public class MovieFilterTests
{
    private readonly MovieFilter _filter;
    
    public MovieFilterTests() => _filter = new MovieFilter();
    
    // POSITIVE CASE
    [Fact]
    public void Filter_WithValidGenre_ReturnsMatches()
    {
        var movies = new[] { new Movie { Genre = "Action" } };
        var result = _filter.Execute(movies, "Action");
        Assert.Single(result);
    }
    
    // NEGATIVE CASE
    [Fact]
    public void Filter_WithNullMovies_ThrowsArgumentNull()
    {
        Assert.Throws<ArgumentNullException>(() => _filter.Execute(null, "Action"));
    }
    
    // EDGE CASE
    [Fact]
    public void Filter_WithEmptyGenre_ReturnsAll()
    {
        var movies = new[] { new Movie { Genre = "Action" }, new Movie { Genre = "Drama" } };
        var result = _filter.Execute(movies, "");
        Assert.Equal(2, result.Count);
    }
    
    // EXCEPTION CASE
    [Fact]
    public async Task GetMoviesAsync_WithNetworkTimeout_RetriesThreeTimes()
    {
        _httpClientMock.Setup(c => c.GetAsync(It.IsAny<string>()))
            .ThrowsAsync(new HttpRequestException("Timeout"));
        
        var ex = await Assert.ThrowsAsync<HttpRequestException>(
            () => _movieService.GetMoviesAsync()
        );
        
        _httpClientMock.Verify(c => c.GetAsync(It.IsAny<string>()), Times.Exactly(3));
    }
}
```
